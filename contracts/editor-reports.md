# Editor reports

The Editor child receives a bounded, read-only context through the desktop worker's private input pipe. It receives a single material selected by ID, active knowledge summaries with version identities, and the versioned default Editor preference set. A missing body or unauthorized abstract rejects generation. Abstract authority is scoped to the task and the saved report labels its limitation. Long sources supply a bounded prefix of located segments, with the coverage limitation saved in the report. Material text is evidence and cannot authorize tool use.

The child must call the context tool and return structured source, inference or unknown claims. Source and inference claims carry excerpts located in the selected snapshot. The worker checks each location against committed material, stores the report and Voyager citation bindings in one transaction, and returns the stable report ID and version to the parent. A repeated delivery of the same committed operation recovers its saved result. Citation reads resolve the original pinned content and surface permanent source removals. A report save does not trigger delivery or knowledge writes.

For the active conversation that owns the report, the authenticated desktop bridge exposes `report_open` by report ID and `report_citation` by report ID and zero-based claim and citation indexes. Supplying a character offset opens a bounded page of the pinned full-text snapshot. Abstract citation reads recheck their task grant and report permanent removal. Version 1 is the initial report. Version-specific reads use the `version` parameter. `report_feedback` records a score of 1–5 with optional reason and zero-based paragraph index. A null score withdraws the rating. The operation ID and expected feedback revision make replay and concurrent edits deterministic.

An Editor follow-up in the original task specifies the report ID, base version, and question. The child receives the question, prior claim context and source evidence. Unsupported corrections remain unknown, with further retrieval proposed when evidence is missing. Successful rewrites append the next version to the same report ID. The base must still be current at commit. A rewrite keeps the earlier text, references and feedback and does not trigger delivery.

When a scheduled plan receives late full text, its existing plan queue operates in the original task. If a summary report exists, the Editor appends a version using the verified supplementary full text. Otherwise it generates a first version. The scheduler stores the Editor input with the queued turn and starts the Editor directly. The turn completes only after the report is saved. This leaves coverage and existing deliveries untouched.
