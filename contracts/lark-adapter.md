# Desktop Feishu adapter

The optional desktop adapter uses Windows x64 Feishu CLI 1.0.99. Installation verifies the pinned SHA-512 npm integrity, the matching upstream release checksum, the selected release members and the actual CLI version. Horizon uses the verified packaged Node runtime for the npm metadata check. It executes the native CLI directly under the desktop process job with no console. Installations live under the current Horizon data home. A fixed upstream mirror can supply the same pinned archive if the official host cannot be reached. Installation does not require npm, global CLI tools or PATH. A failed download or pre-publication check leaves an existing installation untouched.

The desktop bridge exposes setup status, installation and validation, credential entry, the developer console authorization QR code, and a read-only bot identity probe. The App Secret and App ID are stored by the backend in a current-user DPAPI record. The official CLI receives the decrypted account through its process-scoped environment credential provider with bot-only strict mode and a private config directory. No credential field appears in setup replies, diagnostics or Agent conversation. The application ID may appear in the app-specific developer console URL. The setup form does not retrieve a saved secret.

The authorization hyperlink and QR code encode the same developer console address. The Explorer configures application permissions and requests the permitted release in the Feishu developer console. Bot verification only checks the identity endpoint and returns allowlisted permission evidence. Message subscription, card callback and direct-message binding are displayed separately as pending until their actual event/identity checks run. Configuration and install require no message transmission.
