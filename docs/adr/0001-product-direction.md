# Frontier 产品定位与交互决策

状态：已确认。日期：2026-11-07。依据：用户在本次产品讨论中确认的四部分闭环。

Frontier 是面向各行各业持续学习者的资料获取、知识管理与个性化解读助手。科研人员是用户群之一，论文是资料来源之一。本决策取代此前以科研对话、论文报道、飞书知识库或飞书专属反馈界面为中心的产品定位。

## 四个组成部分

1. **资料获取**：围绕用户关注的主题检索论文、新闻、推送、博客等网络原始资料，保留可追溯的来源，供解读与知识构建使用。
2. **知识库管理与构建**：由 Frontier 自建知识管理套件承接飞书多维表格的能力。知识卡片、命题及关联资料支持 Agent 自动新增和修改，也支持用户手动维护。知识库代表用户已掌握的知识；收藏资料不能直接等同于掌握知识。
3. **个性化解读撰写**：读取新资料、用户已有知识与使用过程中积累的偏好，解释新增内容、与已有知识的关系及其变化，让用户尽快理解并吸收。写作是独立能力，不与投递渠道绑定。
4. **定时推送 Agent**：按用户设定自动执行检索、读取知识和偏好、撰写与投递，承接后续反馈，并形成持续学习闭环。

## GUI 与渠道

Frontier GUI 提供资料管理、知识库维护、推送阅读、评分与谈判交互，以及自动任务和偏好设置。主功能入口围绕推送收件箱、资料、知识库和自动任务组织；对话用于追问解读、纠正理解及协商知识更新。执行轨迹与 Console 是辅助工具，不再主导产品结构。

评分表达阅读体验和价值判断；谈判支持进一步表达偏好、纠正理解、讨论和调整知识更新，不能缩减为点赞或一次确认。

飞书是可选的外接前端交互与投递渠道。Frontier 自身必须提供完整闭环，核心知识库与交互不以飞书账号、多维表格或消息卡片为必要前提。

## 实现边界

这是产品决策，不是功能已完成的声明。本次仅整理文档，不修改程序。既有技术文档中的论文字段、飞书表结构、队列、校验、同步与命令保留为现有实现参考，不构成新的产品限制。不得把旧链路的逐条采纳、单篇格式、串行反馈或控制台入口推广为所有未来场景的强制交互。

自建存储的具体技术选型、迁移方案、自动更新与谈判的具体规则，须在后续实现设计中确定；本决策不自行指定数据库、审批机制或页面细节。
