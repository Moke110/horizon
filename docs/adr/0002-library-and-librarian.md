# 图书馆与图书管理员

Horizon 将知识库重定义为独立模块图书馆（Library），并将 Keeper 调整为独立模块图书管理员（Librarian）。图书馆拥有内容及其关系，管理员拥有审核和确认流程。未来外部软件可以通过适配完整承接三个子模块的核心读写能力，同时沿用 Horizon 的审核、交互与检索流程。本阶段暂不开发外部适配。本决策更新 [产品方向](0001-product-direction.md) 中的知识管理模型。

## 图书馆的三个子模块

- **百科（Hpedia）**管理术语、问题和前沿。每个术语沿用对应知识卡片的身份、结构和释义。每个问题包含具体题干及其解答，两者合计至少显式引用一个术语。问题的入站引用仅允许来自白板链接。
- **白板（Bulletin Board）**展示百科中所有追踪中的术语、问题和前沿链接。开始追踪时加入链接，停止追踪时移除链接。
- **资料库（Archive）**管理原始报道来源记录及其原文引用，包括关联 PDF 的引用。文件由现有文件存储负责，生成的 HTML 解读归其产出模块。

## 术语和问题的状态与追踪

可靠的阶段性解答也值得继续研究。百科为术语和问题分别记录内容是否有效（`status`）和是否追踪（`followed`）。新建条目默认有效、未追踪。标为存疑时自动开启追踪，存疑期间锁定为是。恢复有效时保留追踪并解锁，由用户决定何时停止。归档、删除等生命周期信息单独保留。

迁移时优先采用明确记录的收敛状态。已收敛迁为有效、未追踪，尚未收敛迁为有效、追踪中，释义矛盾或重大矛盾迁为存疑、追踪中。术语仅有旧存疑标记时，真值迁为存疑、追踪中，假值迁为有效、未追踪。

综合报道可以引用已计入已知、来源齐全且可用的有效术语，无论是否追踪。存疑术语排除在已确认知识之外。

## 前沿与进展

前沿（Frontier）是探索者关注的开放问题，可以只有题目，也可以积累进展（Update）。百科保留前沿的进展、Voyager 检索入口和检索历史。前沿只有追踪选择，新建时默认追踪。旧「关注中」迁为追踪中，旧「已暂停」和「已解决」迁为未追踪，保留原有解决记录。用户在百科中可查看并标记解决；标记解决时自动停止追踪，单独停止追踪不产生解决记录。每条进展描述一项可独立理解的变化，可以引用多个资料库来源。删除最后一条进展后，前沿及其追踪选择继续保留。

## 读写与确认

图书馆的业务读写接口仅供图书管理员调用。Agent、GUI、Voyager 和自动任务通过管理员访问。管理员对外提供读写及确认消息收发接口。读取直接返回。新增、修改、删除、导入及批量变更先经管理员自动审核，再向发起变更的 Agent 会话或 GUI 发送确认卡片。管理员收到用户确认后执行卡片所示变更。

发出卡片时锁定涉及的已有实体，锁定持续到收到反馈或发卡满 72 小时。锁定期间实体仍可读取，其他写入须等锁解除。到期的卡片自动失效并解除锁定。用户确认选项后移除卡片按钮，重复提交同一确认返回原执行结果。

## 旧数据与测试内容

百科沿用已有术语、问题和前沿的身份，保留条目间的引用、进展及历史。

开发期间由 Agent 生成的测试术语、问题、来源记录、前沿和进展均在各自条目上标记「测试」。清理时管理员列出匹配项及受影响的引用，请求确认后执行。真实前沿下的测试进展按进展条目清理，白板派生链接随原条目变化。
