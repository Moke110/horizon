# 图书馆与图书管理员

Horizon 将知识库重定义为独立模块图书馆（Library），并将 Keeper 调整为独立模块图书管理员（Librarian）。图书馆拥有内容及其关系，管理员拥有审核和确认流程。未来外部软件可以通过适配完整承接四个子模块的核心读写能力，同时沿用 Horizon 的审核、交互与检索流程。本阶段暂不开发外部适配。本决策更新 [产品方向](0001-product-direction.md) 中的知识管理模型。

## 图书馆的四个子模块

- **词典（Dictionary）**沿用现有知识卡片的身份、结构和内容。一个术语（Term）对应一张卡片，释义一个词汇。
- **百科（Hpedia）**由问题（Question）组成。每条包含具体题干及其解答，两者合计至少显式引用一个词典术语。问题的入站引用仅允许来自白板链接。
- **白板（Bulletin Board）**展示尚未收敛或释义有矛盾的术语链接，以及尚未收敛或存在重大未解决矛盾的问题链接。词典和百科保存内容及收敛状态，白板根据该状态生成或移除链接。白板还直接管理前沿。
- **资料库（Archive）**管理原始报道来源记录及其原文引用，包括关联 PDF 的引用。文件由现有文件存储负责，生成的 HTML 解读归其产出模块。

## 前沿与进展

前沿（Frontier）是探索者关注的开放问题，可以只有题目，也可以积累进展（Update）。前沿承接既有关注状态、Voyager 检索入口和检索历史。每条进展描述一项可独立理解的变化，可以引用多个资料库来源。删除最后一条进展后，前沿及其关注状态继续保留。

## 读写与确认

图书馆的业务读写接口仅供图书管理员调用。Agent、GUI、Voyager 和自动任务通过管理员访问。管理员对外提供读写及确认消息收发接口。读取直接返回。新增、修改、删除、导入及批量变更先经管理员自动审核，再向发起变更的 Agent 会话或 GUI 发送确认卡片。管理员收到用户确认后执行卡片所示变更。

发出卡片时锁定涉及的已有实体，锁定持续到收到反馈或发卡满 72 小时。锁定期间实体仍可读取，其他写入须等锁解除。到期的卡片自动失效并解除锁定。用户确认选项后移除卡片按钮，重复提交同一确认返回原执行结果。

## 旧数据与测试内容

切换到新版百科时清空现有临时命题，移除相关白板链接，新版百科从空集合开始。词典沿用现有知识卡片。

开发期间由 Agent 生成的测试术语、问题、来源记录、前沿和进展均在各自条目上标记「测试」。清理时管理员列出匹配项及受影响的引用，请求确认后执行。真实前沿下的测试进展按进展条目清理，白板派生链接随原条目变化。
