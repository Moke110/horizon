# 资料库与不可变报道

百科只管理术语、问题和前沿。百科进展可按 ID 引用资料库文档或报道，但不拥有它们：删除进展不删除资料，资料入库也不要求先有百科条目。两者仍属于 Library，经 Librarian 访问。本决策更新 ADR-0002 的原文归属。Horizon Newsroom 取代 Editor，负责生成报道；Archive 负责持久保存。Newsroom 的内部设计另定。

## 先选留，再登记

源文档是用户提供或 Agent 搜集的一份原始文件。下载后先进入 Agent 缓存；Agent 依据标题、主要内容、学术引用信息等自行判断、去重、选留，不以哈希或相似度设硬性去重标准。Librarian 不替 Agent 做内容判断；按既有确认流程检查并写入。首次采集登记必须提交恰好一份源文件，由 Librarian 校验 SHA-256 并持久化文件与条目。

文档条目包含标题、永久 Horizon ID、简介、源文件 SHA-256 和可选文件地址；学术引用信息可选。文档和报道的 ID 分别以 `d-`、`r-` 开头，后接 32 位小写十六进制主体。一个已注册的文档 ID 永远指向同一份源文件；若决定收录另一份文件，必须新建 ID，不得换源。跨工作区导入既有条目可只保留原 ID 和哈希而没有文件地址；仅有标题或网址不足以登记。找回哈希相同的文件可以恢复访问。

## 先检索，再撰写

Agent 工作流必须在一次报道任务中完成全部检索后才开始写作。草稿只在缓存中，不设「撰写中」状态。新生成的报道以已完成的 HTML 与报道条目一同入库。报道条目与文档条目的基本字段对称，哈希对应报道 HTML，另有非空的 `covered-docs`：只列实际报道的文档，不列未采用的输入或仅作背景的引用。同一文档可被多篇报道覆盖。

导入已有报道时可无 HTML，须保留原 ID、哈希并显示原文不可用。导入时找不到的文档条目逐个原位替为 `d-unknown`，不合并、不建占位条目；文档条目存在而仅原文件离线时保留真实 ID。入库后不回填，不因缺失引用降低可信度。

## 可信度可重评，报道不可改稿

报道入库后 HTML 和条目均不可改写。可信度判断单独关联报道 ID，初始为「已完成」。后续任务只有在源文件存在重大研究方法错位、诚信缺陷，或 Agent 对源文件解读错误时才可降低可信度。有具体证据但影响待核实时标「存疑」；已确认主要解读不可靠时标「失效」，无须先经过「存疑」。观点冲突本身不是降级依据。每次变更保留理由和依据，查明误判后可以恢复；重评不产生报道版本。

取消报道版本与冲突处理系统。若需更新内容，另起任务，以新 ID 撰写新报道并注明取代的旧报道。仅在新报道成功入库后删除旧条目和旧 HTML；新报道入库失败则保留旧报道。旧 ID 不重用，既有引用显示「报道已删除」，不重定向到新报道。
